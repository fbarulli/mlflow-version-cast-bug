# MLflow 3.14.0 PostgreSQL Model Registry Failure: `model_versions.version` bound as VARCHAR

## Summary

MLflow 3.14.0 fails to retrieve registered model versions from a PostgreSQL backend when using the REST model registry API.

The failure occurs because the SQLAlchemy query generated by MLflow binds the model version parameter as `VARCHAR`, while the PostgreSQL column `model_versions.version` is an `INTEGER`.

PostgreSQL does not allow comparison between these types:

    integer = character varying

This causes `MlflowClient.get_model_version()` to fail.

---

## Environment

    MLflow: 3.14.0
    SQLAlchemy: 2.0.51
    psycopg: 3.3.4
    Python: 3.12
    PostgreSQL: 16.x

Backend store:

    postgresql+psycopg://mlflow:mlflow@postgres:5432/mlflow

---

## Database schema

The MLflow database schema contains:

    \d model_versions

Relevant column:

    version | integer | not null

Full relevant definition:

    name              | character varying(256)
    version           | integer
    workspace         | character varying(63)

## Steps to reproduce

### 1. Start MLflow server with PostgreSQL backend

    mlflow server \
      --host 0.0.0.0 \
      --backend-store-uri postgresql+psycopg://mlflow:mlflow@postgres:5432/mlflow

### 2. Register a model

Example:

    import mlflow
    from sklearn.datasets import load_diabetes
    from sklearn.ensemble import RandomForestRegressor

    mlflow.set_tracking_uri("http://mlflow:5000")

    mlflow.set_experiment("test")

    with mlflow.start_run():

        X, y = load_diabetes(return_X_y=True)

        model = RandomForestRegressor()
        model.fit(X, y)

        mlflow.sklearn.log_model(
            model,
            name="model",
            registered_model_name="demo-model",
        )

### 3. Retrieve model version

    import mlflow

    client = mlflow.MlflowClient()

    client.get_model_version(
        "demo-model",
        3,
    )

## Expected behavior

A ModelVersion object should be returned.

Example:

    ModelVersion(
        name="demo-model",
        version="3",
        status="READY"
    )

---

## Actual behavior

The request fails with:

    mlflow.exceptions.RestException:
    BAD_REQUEST:
    (psycopg.errors.UndefinedFunction)
    operator does not exist:
    integer = character varying

---

## Generated SQL

The failing query:

    SELECT model_versions.workspace,
           model_versions.name,
           model_versions.version
    FROM model_versions
    WHERE model_versions.workspace = %(workspace_1)s::VARCHAR
      AND model_versions.name = %(name_1)s::VARCHAR
      AND model_versions.version = %(version_1)s::VARCHAR
      AND model_versions.current_stage != %(current_stage_1)s::VARCHAR

Parameters:

    {
        "workspace_1": "default",
        "name_1": "demo-model",
        "version_1": "3",
        "current_stage_1": "Deleted_Internal"
    }

The problematic comparison:

    model_versions.version = '3'::VARCHAR

---

## PostgreSQL error

    psycopg.errors.UndefinedFunction:

    operator does not exist:
    integer = character varying

PostgreSQL reports:

    No operator matches the given name and argument types.
    You might need to add explicit type casts.

---

## MLflow source location

The issue appears in:

    mlflow/store/model_registry/sqlalchemy_store.py

Function:

    _get_sql_model_version()

Current condition:

    conditions = [
        SqlModelVersion.name == name,
        SqlModelVersion.version == version,
        SqlModelVersion.current_stage != STAGE_DELETED_INTERNAL,
    ]

The version value arriving through the REST API path is treated as a string.

---

## Additional investigation

The ORM model defines:

    version = Column(Integer, nullable=False)

Direct SQLAlchemy usage works:

    session.query(SqlModelVersion).filter(
        SqlModelVersion.name == "demo-model",
        SqlModelVersion.version == 1,
    ).all()

This generates:

    model_versions.version = 1

and succeeds.

The failure only occurs through the MLflow REST registry API path.

---

## Possible fix

Explicitly bind the parameter as an integer:

    from sqlalchemy import bindparam, Integer

    conditions = [
        SqlModelVersion.name == name,
        SqlModelVersion.version == bindparam(
            "version",
            value=int(version),
            type_=Integer(),
        ),
        SqlModelVersion.current_stage != STAGE_DELETED_INTERNAL,
    ]

This ensures SQLAlchemy sends an INTEGER bind parameter instead of VARCHAR.

---

## Impact

Affected operations include:

- MlflowClient.get_model_version()
- Model registry operations that internally retrieve a specific model version

This prevents retrieving registered model versions when using PostgreSQL as the MLflow backend store.
